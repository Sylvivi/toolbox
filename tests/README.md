# 回归测试

一句话：**一段"替人点一遍"的小程序**。它用一个看不见的浏览器打开 `index.html`，
自己点按钮、自己检查结果对不对，不用人盯着。

```bash
bash tests/run.sh
```

全过就是一片 ✅ 加一句「36 条全过」；有问题会红一行，写清哪条不对、实际是什么。

**不花钱、不联网。** 所有模型请求都是假的（`chatStreamChat` 被换成写死的假回复），
跑一遍只用 40 秒左右的本机时间，不消耗任何中转站额度。

## 现在覆盖了什么

只有「标背景」这一个功能——因为它是返工最多的地方，而且每一轮都是在真机上
花着额度才发现的。里面每一条断言都对应一个真实踩过的坑：

| 组 | 钉住的是 |
|---|---|
| A 参数护栏 | 两遍的 `max_tokens` 都不许调回小值（思考型模型光"想"就能花光，正文一字不吐） |
| B 讲解人设 | 小说走小说人设、社科走社科人设，都不许混进共读点评那套 |
| C 第一遍扫描 | 清单格式容错、跨章去重、按小节的区间限制、摘要模型挂了自动换主模型 |
| D 空清单 | 四种情况必须分开报，不许混成一句"没有新的背景" |
| E 端到端 | 块要**真的插进正文**，且 reader_qa 里的条数对得上 |
| F 按小节 | 目录段号 = 阅读器段号（曾差 1），节外段号一条都不许插 |
| G 进度条 | 层级盖过 modal、待在上半屏不抢拇指区、停止键点得到、不积攒监听器 |

## 加新测试

在 `tests/` 下新建 `*.test.js` 就会被 `run.sh` 自动带上。照抄 `bg.test.js` 的写法：
`ok(名字, 条件, 出错时打印什么)` / `eq(名字, 实际, 期望)`，最后按失败条数决定退出码。

## 环境

`playwright`（那个假浏览器）装在仓库外的 `~/.toolbox-test/`，18M，不进公开仓。
换机器要重装一次：

```bash
mkdir -p ~/.toolbox-test && cd ~/.toolbox-test && npm i playwright && npx playwright install chromium
```

## ⚠️ 写测试时最容易踩的一个坑

插入背景块会**整段重渲染**，之前拿到的 DOM 节点当场作废。
`await readerMarkBg(...)` 之后必须**重新 query 一次**，
拿旧节点去数 `blockquote` 永远是 0——写这套测试时第一版就栽在这里。

## ⚠️ 第二个坑：`getComputedStyle` 返回的是活对象

元素之后被重渲染换掉，再去读那个对象就全是空串——报告"样式没生效"，其实是节点没了。
**当场取成字符串**再传出来。（写长按那组测试时又栽了一次。）

  另外钉住「正文不在你点的那条消息里」（在前面那条 user 消息里）——第一版就栽在这。
