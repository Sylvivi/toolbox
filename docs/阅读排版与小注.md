# 阅读排版·字体·手写小注

> 从 `CLAUDE.md` 拆出的功能笔记（2026-08-06 拆）。**动这块代码之前先整本读一遍**——里面每条 ⚠️ 都是踩过的坑。

- **共读正文可调**：正文字号（`--reading-fs`/`reading_font_scale`）、段间距（`--reading-pspace`/`reading_para_space`，2~28px 默认8）。段落带行内 `margin:0.5em 0`，改间距的 CSS 必须 `!important` 才盖得过行内样式。批注框 `blockquote[data-cp]` **只吃自身上边距、贴住它点评的那一段**，不随段间距推开。

- **手写小注（2026-08-04/05 做）**：选中一个字/词 →「✍️ 注」→ AI 回一句 `拼音·意思` → 用中文花体写在段间的缝里，一根手绘引线指回那个词。用户原话「有些个别的字我不会读，或者不知道意思，不需要用一整段话来介绍」。
  - **零新增存储**：一条小注＝一条划线（`reading_highlights`）的 `note` 字段。云同步/换设备/删除/读痕面板全部白拿，颜色也复用划线那 5 个。
  - **⚠️⚠️小注和引线必须挂在**整个正文容器上单独一层（`.rd-gl-layer`）、**绝不能进 `<p>` 里**。点击翻页 `readingPageDown` 靠 `range.selectNodeContents(p).getClientRects()` 逐行量位置，塞进段落的绝对定位元素会被当成「一行」、翻页翻歪——那是读小说时每分钟都在用的手势。
  - **⚠️锚点按「行片段」算，`getBoundingClientRect()` 在这里是错的**：① 选中的字跨过人名高亮会被拆成好几个 mark；② 词本身跨行折断（「诸侯皆缟／素」）时那个大框的中心落在两行之间的空白里，箭头直接指飞。收齐所有 `getClientRects()` 片段 → 按行分组 → 往上锚第一行、往下锚最后一行。
  - **⚠️永远不许把段间的缝撑高**（用户明确：「不要把那个缝撑高好吗，我担心会影响到行号什么的」）。放不下就换另一条缝、或者往左让位，**不改版式**。上下有多少空当**必须实测兄弟节点**、不能假设就是段间距——紧跟段落的批注框 `blockquote[data-cp]` 不吃段间距，那道缝只有 ≈5.6px。
  - **⚠️「这一行满了」＝已经摆好的那条挡住了，不是「够不到右边界」**（2026-08-05 修）。`_gl_try` 原本把「想放的位置伸出段落右边」也算满 → 另起一行 → 整条抬高约 28px 压进上一段正文。用户报的那条只超出 **3px**，而那条缝里就它一条。「离目标字 22px」只是手感偏好、本来就该让位；先贴右边界再试，撞了才换行。**越宽的小注越容易踩**，所以症状像随机发作。回归 `tests/gloss.test.js` S 组。
  - **⚠️拼音和中文是两种花体，按「·」切开**：拼音锁死用「溪涧山雪璞玉浑金」（唯一声调齐全的），中文用她偏爱的「青春例外你是偏爱」（缺字回退溪涧）。**别写成「青春优先、逐字回退」**——青春是有 a~z 的、只缺 17 个带调元音，那样 `shēng` 会变成 sh(青春)+ē(溪涧)+ng(青春)，一个词三种笔迹。
  - **⚠️墨色和划线底色是两套颜色、互不影响**（2026-08-05 修）：底色是 `mark.rd-hl.rd-hl-*` 的 rgba 背景（用户说日间的底色**刚好、别动**），`.rd-gl-*` 只管笔迹。日间原本借用「下划线样式」那 5 个色，但那套是给一条线调的，当花体字（笔画细 + opacity）在浅背景上太淡——金色对比度只有 **2.0**。现日间单独压深到 5~6:1 且不打透明度折扣，**夜间维持原样**（用户满意）。
  - **⚠️⚠️拆 DOM 壳子一律「把孩子搬出来」，别用 `textContent` 压平（2026-08-05 修）**：用户报「先写的小注，标背景之后那个被解释的词的小注就不见了」。根因在 `readingRehighlightNamesInPlace` 拆旧人名 span 那句 `replaceChild(createTextNode(s.textContent), s)`——**划线 `<mark>` 正套在 `.reading-name` 里面**（标背景收尾会把讲过的词并进名单高亮，而她写小注的正是同一个词，两件事撞在同一个词上），一压就把 mark 连同 `data-gl` 一起抹掉，**划线和小注一起消失**。**⚠️数据一直是好的、只是 DOM 被抹**，重开一章又回来，所以看着像随机发作、也容易误判成「小注排版丢条」。**排查记录（省得再走一遍）：先后否掉了「词进名单挤掉小注」「背景块占了段间那道缝导致丢条」「被背景块盖住」三个猜测，都是实测否的**——真正定位靠**跑真的 `readerMarkBg` 循环**（假请求）而不是手工插块，修前「划线 mark 数 1→0」当场现形。回归 `tests/gloss.test.js` U 组（4 条；A~T 已被占满，新组从 U 起）。
  - **⚠️引线交叉的第二种成因：排序键里混进了标签宽度（2026-08-05 修）**。第一种是「舍近求远」（跨行的词只算一份 want，已修）。这次是用户截图《史记的读法》「…**撮**名法之要…」：`撮`(小注宽 89) 和 `名法`(小注宽 156) 两个字才差 21px。摆位是「按排序从左往右占位」，而老排序键写的是 `字x + 方向偏移 − 标签宽/2`（＝标签想放的位置）——**宽的减得多**，于是宽的那条被排到前面、先占左边，字是左→右标签却右→左，必然交叉。**排序键只能用目标字的位置；标签宽度决定「摆在哪」，不决定「谁先摆」。** 修完那两条会自动分到两条缝（放不下就换缝是既有退路，比挤在一条缝里交叉好）。回归 `tests/gloss.test.js` V 组。
  - **浮动小条上没有「问」**（用户几乎不用，两个条上都撤了）；「✍️ 注」放在**色板后、划线前**（高频功能，位置是她定的）。常见字可以不写拼音。

- **共读点击翻页按行对齐**（`readingPageDown`）：用 `Range.getClientRects()` 找「本页最后一行完整露出的行」滚到容器顶部——新页顶行 = 上页读到的最后一整行（保留一行接头），永远不切半。找不到行或目标太近(<60px)退回整屏滚。极小瑕疵：开「画框」时顶边可能露上一行画框底描边 2~4px，文字不切。

- **字体槽位（7 个）**：`READING_FONT_SLOTS` = 正文/引号/短句/标题/人名/精句 + **缺字**。前六个各写一个 CSS 变量；「缺字」（`isFallback:true`）不写变量，而是接在**装饰槽位**字体链尾巴上（`"主字体", "缺字字体", serif`）——**正文那条链不接**，用户明确要求正文一个字不动。花体做子集常漏生僻字（「苼」在 GBK 不在 GB2312，实测国产花体基本都不收），浏览器逐字回退，主字体有的字轮不到兜底。槽位选「默认」时**照旧不写变量**：靠 CSS `inherit` 继承父级算好的整条链，兜底会跟着继承过来，在这里补反而会切断继承。
  - ⚠️ **加新槽位必须同时改两处**：`READING_FONT_SLOTS` 和 `cfBuildManifest()` 里那个**手写死的** `fontSlots` 对象（不是从槽位表推的）。只加前者的话，`readingApplyFontSync` 会在云端较新时把新槽位 `removeItem` 掉，表现是「当场好好的、过几小时自己消失」，肉眼根本查不出来。测试 `tests/font.test.js` A 组钉住。
  - **⚠️「标题字体」只作用在 `.reading-merged .reading-chap-title` 上，而这个 class 原本只靠 `READING_TITLE_RE` 猜（2026-07-30 修）**：那条正则要求同时满足「`第X章/节/回/篇/卷/话` 开头 + 后面 ≤20 字 + 不含逗号句号问号顿号」，所以**凡是不长成传统章回体的章名一律拿不到标题字体**——用户导进来的知乎存档三本，章名是「【商业经济】教育家 - 为什么，这几年…？」，连改写成「第一章 为什么，…？」也照样不认（有逗号问号）。**数据侧无解**：要过正则就得把章名砍到 20 字内且不带标点，那既看不出讲什么、也搜不到了。修法是**阅读模式不用猜**——`readerChapterPair` 本来就把章节标题拼在正文最前面（「标题占掉 P1」），所以 `chatReaderMode && p === 0` 直接认，和原正则**并联**（共读模式一字不动：那边正文是发进来的，P1 不保证是标题）。⚠️另加 `length <= 120` 兜底，万一某本书 P1 不是章名而是正文首段，别把一整段套上花体糊成一团。⚠️**`_readingMergeCache` 的签名必须带 `rdMode`**：同一段文字在两种模式下该不该包这个 class 不一样，不带会串出**隐形的错样式**。测试 `tests/chaptitle.test.js`（7 条）。
