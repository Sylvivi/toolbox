# 切章与目录

> 从 `CLAUDE.md` 拆出的功能笔记（2026-08-06 拆）。**动这块代码之前先整本读一遍**——里面每条 ⚠️ 都是踩过的坑。

- **⚠️「第十回排在第一回前面」＝空壳章被正文里那行回目改了名（2026-08-02 修）**：用户报《笑傲江湖（新修版）全4册》目录乱序。**服务器那份数据是好的**，坏在导入管线：`rbDeriveTitleAndBody` 会翻每章正文**前 8 个非空行**，看到像回目的行就拿来当章节名（这是治「epub 把每章 `<title>` 都设成书名」用的，本身有用）。而金庸这套 epub 每卷开头有个**卷首目录页空壳**——`<h1>` 是本卷**第一回**的回目、肚子里只有一行本卷**最后一回**的回目（`第一回 灭门` / 正文只有 `第十回 传剑` 6 个字）。于是那个壳被改名成「第十回 传剑」、正文同时清空，目录里凭空多出个 0 字假章节卡在真正的第一回前面。用户那份还叠了一次「重新拆分」，把 0 字空壳和后面的图辑/新序并成一章，显示成「第十回 传剑 **6,087 字**」。
  - **⚠️这个 bug 在目录上完全看不出来，只有字数暴露它**（假的 6,087 vs 真的 24,084）。写这类断言别只比标题，要比「有没有正文空了却还叫着回目名的章」。
  - **修法**：揪完正文空了 ＝ 那行是这一章**仅有的内容**、不是它的标题，保留原标题（`headIdx >= 0 && !newBody.trim() && t`）。只兜「从正文里揪的」这一路，不动 `_rbIsBareChapterNum` 那条正常路，**章数一个不动**。测试 `tests/shelltitle.test.js`（12 条，含拿服务器上那本真书跑整条管线）。
  - **⚠️同一个函数的第二种坏法：epub 的「分册目录页」（2026-08-02 查《三体》第一部时发现）**。那一页正文就是一串章节名（`第一章 科学边界 / 第二章 台　球 / 第三章 射手和农场主 / 第四章 三体、周文王、长夜 / …`），`rbDeriveTitleAndBody` **把第一条揪走当了标题**，接着那趟「跳过重复的标题行」又吃掉了第二、三条，**吃到「第四章 三体、周文王、长夜」时因为标题里有个顿号、`READING_TITLE_RE` 不认才停下**。结果：目录页顶着「第一章 科学边界」这个名字排在真正的第一章前面（症状同《笑傲江湖》），而且页里前三条被永久吃掉。**这种不是空壳（604 字），上面那道「正文空了就不改名」的闸拦不住它**。**排查提示：目录里出现「同名两章、一个几百字一个几千字」，先去看那个短的正文是不是一串章节名。**
    - **当时判断「误伤风险大、先只改数据」是错的，第二天就打脸了（2026-08-03 补代码修）**：我在服务器上把标题改回 `三体I`，用户一拉，手机上又变成了「第五章 叶文洁 475 字」排在第一章前面。原因是 **`rbLoad` 的一次性标题修复按 `bk._titleFixVer` 判，而云端下回来的书身上没有这个标记**——每重新下载一次就重跑一遍、**每跑一遍再啃掉一口**（604 字 → 475 字；这次揪走的是第五章，因为第四章带顿号过不了正则）。**教训：只要坏在导入/修复管线上，改服务器数据是挡不住的，同步一次就打回原形，必须在代码里拦。**

  - **⚠️同一个函数的第三种坏法：章首「题词」被当成副标题剪走（2026-08-03 修，用户报《米德尔马契》「目录会把正文的第一句跟标题的第几章连在一起」）**。这本书每章开头有一段**题词**（引诗/引语），按诗行折行，第一行自然以逗号收尾；而 epub 里章标题就是光秃秃的「第一章」，于是 `_rbLooksLikeSubtitle` 那条「逗号对偶回目」的规矩（`/[，、]/ && ≤12字 && 不以虚词收尾`）把题词首行当成副标题接了上去 → 目录变成「第一章 我身为弱女子行不了大善，」。**⚠️两处伤，第二处更重：正文那一行同时被剪走了**，这一章从题词第二句开始、半句话没头没脑——而目录上只看得出标题变长，看不出正文缺了字。全书 97 章中招 27 章。

- **⚠️「每章都在重复」＝拆章把首行当章节名却没从正文删（2026-07-28 修）**：用户截图——章节名在正文开头又出现一遍，**每个长段落前面还躺着一条「它自己的前 80 字」**。根因是 `rbSplitByPattern` 的 `__EMPTY_LINE__` 分支：`lines[0].substring(0,80)` 当章节名、**整块（含首行）仍留在 body 里**；之后书在「回拼 rawText（`title + '\n\n' + body`）→ 重新拆分」转一圈，那条半截话就被**写死进正文**、再也拆不掉。**比对过 Readingo 原始 txt，源文件是干净的——是导入管线弄坏的**，别去怀疑书源。波及真实书库 **86 本 / 2206 处半截段 + 36 本 / 310 章标题重复**。

- **⚠️加了「番外」这条切章规则（2026-07-28）**：用户追加番外时把标题写成 `番外一、`，切不出来——`cn-num-dot` 要求**行首第一个字就是中文数字**，前面多了「番外」两字就不认，整篇被切成一坨、兜底命名成「前言 / 引言」（她问「它为什么会自己取名叫前言呀？」）。她书库里 `番外·xxx` 有十几本，值得单列。**四处配套**：`RB_PRESETS.fanwai` ＋ `rbAutoSplit` 探测表 ＋ 目录的「切法」下拉（`#rbPresetSelect`）＋ 追加章节预览框的 `opts` 数组。
  - **⚠️正则两道闸都不能少**（写测试时当场踩到）：① 整行 ≤22 字；② **「番外」后面必须跟分隔符/序号或到此为止**。只卡长度的话「番外正文甲。」这种短句也会被当成章节名 → 真标题下面变空 → 被 `rbSplitByPattern` 末尾那句 `filter(c => c.body.length > 0)` **静默丢掉**，番外反而整个消失。（顺带记下：**标题行下面没有正文时，那一章会被无声丢弃**，这是老行为。）
