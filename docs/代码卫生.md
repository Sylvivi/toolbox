### 1. 死代码：声明了但没人调用

import re

### 2. 重复代码块（最能抓出「改了这边没改那边」）

```bash
python3 - <<'PYEOF'
import collections, hashlib, re
s=open('index.html',encoding='utf-8').read()
L=[l.strip() for l in s.split('\n')]
seen=collections.defaultdict(list)
for i in range(5700, len(L)-10):          # 5700 起＝跳过 CSS 区，主题定义天然重复
    blk=L[i:i+10]
    if sum(len(x) for x in blk) < 300: continue
    seen[hashlib.md5('\n'.join(blk).encode()).hexdigest()].append(i+1)
fns=[(s[:m.start()].count('\n')+1, m.group(1)) for m in re.finditer(r'\n\s*(?:async\s+)?function\s+([A-Za-z_$][\w$]*)', s)]
def owner(line):
    cur=None
    for ln,n in fns:
        if ln<=line: cur=n
        else: break
    return cur
for v in [v for v in seen.values() if len(v)>1]:
    print(f'  行 {v} → {[owner(x) for x in v]}')
PYEOF
```

**基线：应该是 0 处。** 2026-08-06 清理前是 12 处，全部抽成公用函数了。
再冒出来就说明又有人复制粘贴了——去看第三节那条教训。

## 三、本轮修掉的东西 + 教训

### ⚠️最大的一条：同一段逻辑存在两份，一定会分叉

`importAllData`（导入备份）和 `applySyncData`（云同步）里有一段逐字相同的合并代码。
云同步那边修过两次，导入这边一次都没跟上：

1. **墓碑检查只有云同步有** → 点「导入备份」会把早就删掉的密钥/收藏原样复活，
   而且删除记录被抹掉后，复活的条目下次还会被推上云。
2. **集合外层字段（标题/标签）合并只有云同步有** → 导入只合并 items，集合改过的名字停在旧值。

补第②条时测试立刻红了，顺带挖出**云同步那份其实也是半残的**：
它在 `if (changed)` 里先写了 `localItem.updatedAt = d.updatedAt`，
下面再拿同一个条件判断外层字段要不要跟——那时两边已经相等、条件恒 false。
⇒ **只要子条目有任何变化，集合的标题就永远不跟新**，只有子条目一点没变时那段才生效。

**教训**：这类顺序坑靠读代码很难看出来（两个 if 长得一模一样，谁会想到中间那行改了变量）。
是**先抽公用函数、再写测试**把它逼出来的。现在合并逻辑只剩一份
（`snipMergeCollectionInto`），测试 `tests/importmerge.test.js` 15 条钉住。

这条应该并进 CLAUDE.md 里「同步这类 bug 的三个共性」当**第四条共性**：
**同一段合并逻辑不许存在两份**。
