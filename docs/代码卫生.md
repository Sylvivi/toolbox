## 一点五、什么时候该把单文件拆开

用户 2026-08-06 问的：「到什么程度你会觉得需要拆了」。定下的判据如下——
**光是文件大不是拆的理由；因为大而开始出错才是。**

### 三条我能量的

```bash
# ① 任一功能区 > 6 万 token（＝我一次读不完还留得下干活空间的量）
python3 - <<'PYEOF'
import re
s=open('index.html',encoding='utf-8').read(); L=s.split('\n')
h=[(i+1,m.group(1).strip()) for i,l in enumerate(L) for m in [re.match(r'\s*\*\s*(\[[0-9.]+\].*)',l)] if m]
h=[x for x in h if '—' not in x[1]]
for i,(ln,name) in enumerate(h):
    end=h[i+1][0] if i+1<len(h) else len(L)
    b='\n'.join(L[ln:end]); cn=len(re.findall(r'[一-鿿]',b))
    tok=int(cn*0.75+(len(b)-cn)*0.28)
    if tok>25000: print(f'{tok:>8,}  {name[:44]}{"  🔴超6万" if tok>60000 else ""}')
PYEOF
```

② **重复块扫描 > 3 处且跨不同区**（脚本见下一节第 2 条）——说明在跨区复制粘贴，因为读不到另一边。
③ **全量回归 > 10 分钟，或测试文件 > 60 个**——那时并行也救不了，得按模块只跑相关的。

### 两条用户比我先察觉

④ **同一个功能改两次以上才对**，尤其「修好 A、坏了 B」。
⑤ **反复问她已经答过的项目事实**，或者说「我不确定别处有没有依赖」然后猜错。

### 判定规则

- **只有 ① 亮** → 给那个区**分小节**（纯加注释、零风险），**不拆文件**。
- **④ 或 ⑤ 出现，再加上 ② 或 ③ 任意一个** → 才真的拆，走**「拆文件但不加构建」**那条路
  （老式 `<script src="xxx.js">`，全局作用域不变、代码一个字不用改、不需要构建步骤；
  ⚠️唯一真代价是 service worker 要缓存多个文件，可能出现「HTML 新了但 xx.js 是旧的」错配，这类 bug 极难查）。

### 2026-08-06 的执行记录

① 亮了：`[3.10.5]` 单区 **1.6 万行 / 30 万 token**，占全文一半以上，**单区就超我的上下文上限**。
按规则**没拆文件**，而是切成 `[3.10.5.1]~[3.10.5.13]` 十三个小节（最大的 2086 行 / 3.8 万 token，全部低于 6 万）。
其余 21 个区最大才 4.8 万，结构本来就好——**问题从来不是"单文件"，是那一个区长成了大杂烩**。

⚠️**新增功能请挂进对应小节，别再往那堆里随手加**，否则一年后又会长回一个读不完的块。

### 2. 重复代码块（最能抓出「改了这边没改那边」）

```bash
python3 - <<'PYEOF'
import collections, hashlib, re
s=open('index.html',encoding='utf-8').read()
L=[l.strip() for l in s.split('\n')]
seen=collections.defaultdict(list)
for i in range(5700, len(L)-10):          # 5700 起＝跳过 CSS 区，主题定义天然重复
    blk=L[i:i+10]
    if sum(len(x) for x in blk) < 300: continue
    seen[hashlib.md5('\n'.join(blk).encode()).hexdigest()].append(i+1)
fns=[(s[:m.start()].count('\n')+1, m.group(1)) for m in re.finditer(r'\n\s*(?:async\s+)?function\s+([A-Za-z_$][\w$]*)', s)]
def owner(line):
    cur=None
    for ln,n in fns:
        if ln<=line: cur=n
        else: break
    return cur
for v in [v for v in seen.values() if len(v)>1]:
    print(f'  行 {v} → {[owner(x) for x in v]}')
PYEOF
```

**基线：应该是 0 处。** 2026-08-06 清理前是 12 处，全部抽成公用函数了。

## 三、本轮修掉的东西 + 教训

### ⚠️最大的一条：同一段逻辑存在两份，一定会分叉

`importAllData`（导入备份）和 `applySyncData`（云同步）里有一段逐字相同的合并代码。
云同步那边修过两次，导入这边一次都没跟上：

1. **墓碑检查只有云同步有** → 点「导入备份」会把早就删掉的密钥/收藏原样复活，
   而且删除记录被抹掉后，复活的条目下次还会被推上云。
2. **集合外层字段（标题/标签）合并只有云同步有** → 导入只合并 items，集合改过的名字停在旧值。

补第②条时测试立刻红了，顺带挖出**云同步那份其实也是半残的**：
它在 `if (changed)` 里先写了 `localItem.updatedAt = d.updatedAt`，
下面再拿同一个条件判断外层字段要不要跟——那时两边已经相等、条件恒 false。
⇒ **只要子条目有任何变化，集合的标题就永远不跟新**，只有子条目一点没变时那段才生效。

**教训**：这类顺序坑靠读代码很难看出来（两个 if 长得一模一样，谁会想到中间那行改了变量）。
是**先抽公用函数、再写测试**把它逼出来的。现在合并逻辑只剩一份
（`snipMergeCollectionInto`），测试 `tests/importmerge.test.js` 15 条钉住。

这条应该并进 CLAUDE.md 里「同步这类 bug 的三个共性」当**第四条共性**：
**同一段合并逻辑不许存在两份**。

## ⚠️挪动 HTML 块别用文本切片（2026-09-05 踩的）

她说「间距那一行和简繁那一行交换一下位置」，我用 `find` + 字符串切片把两块对调，
**结束位置算在了内层容器的 `</div>` 上**，于是「间距」整块被塞进了「简繁」那个 div 里面——
界面上看就是两行合并成了一行（她原话「你怎么把那个简繁和间距合并了呀」）。
更糟的是我接着又手工删补闭合标签，越修越偏。

**正确做法**：
1. 挪块之前先从 `git show <上一个提交>:index.html` 取出原样，对照缩进看清每个 `</div>` 各关的是谁；
2. 改完**用真解析器验**，别数标签个数（两段范围不同时数量根本不可比）：
   在无头浏览器里跑一句 `a.parentElement === b.parentElement`、`a.contains(b)`、
   以及 `[...parent.children].map(c => c.id)` 看顺序，比肉眼看缩进可靠得多；
3. ⚠️这类改动**没有报错**——HTML 容错，标签错位照样渲染，只有观感不对。
   所以别指望 `node --check`（它只看 `<script>` 里的 JS）帮你兜住。
